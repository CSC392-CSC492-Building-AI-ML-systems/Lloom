## 2. API formats

The backend returns your fixture shapes where they exist. This section covers the new pieces, plus where each page gets its data.

### 2.1 Statuses
Runs and jobs use the same words:

`Draft` → `Pending` → `Running` → `Completed`, or the run ends `Failed` / `Cancelled`.

`Failed` and `Cancelled` runs can be started again (Retry).

### 2.2 Projects (Home, Create Project, Project overview, Configure Run)
| Call | Returns |
|---|---|
| `GET /projects` | `[{ id, name, lastOpened }]`, newest first |
| `POST /projects` | Multipart: `name`, `description`, `files[]` (CSV or JSON). A bad file returns `422` with a readable `detail` message. |
| `GET /projects/{id}` | `{ id, name, description, lastOpened, datasets: DatasetFixture[], runs: RunFixture[] }`. Runs are newest first, Draft runs include `configuration`, and Completed runs include `concepts`. |

### 2.3 Runs (Review Run, Run in Progress)
| Call | Returns |
|---|---|
| `POST /projects/{id}/runs` | Body: `RunConfiguration` plus optional `name`. Returns the run (below) with status `Draft`. |
| `PATCH /runs/{id}` | Body: `RunConfiguration`. Updates a Draft (Edit configuration / Resume) and recomputes `estimatedCost`. |
| `GET /runs/{id}` | The run (below). **The progress page polls this.** |
| `POST /runs/{id}/start` | Start Run / Retry. Returns `{ jobId }`, and the run becomes `Pending`. |
| `POST /runs/{id}/cancel` | Cancel Run. The run ends `Cancelled` when the current step finishes. |

The run object:
```ts
{
  id: string;
  name: string;
  projectId: string;
  datasetId: string;
  created: string;                  // ISO date
  status: "Draft" | "Pending" | "Running" | "Completed" | "Failed" | "Cancelled";
  configuration: RunConfiguration;
  estimatedCost: number | null;     // US dollars; null = not available
  model: { provider: string; model: string } | null;  // what the run used, set on start
  latestJob: {
    id: string;
    status: "Pending" | "Running" | "Completed" | "Failed" | "Cancelled";
    step: "Distill" | "Cluster" | "Synthesize" | "Score" | null;  // the stage to highlight
    done: number;
    total: number;
    error: string | null;           // set when status is "Failed"
  } | null;                         // null before the first start
}
```

### 2.4 Results (Concept Explorer, Concept details, Document details)
| Call | Returns |
|---|---|
| `GET /runs/{id}/results` | Your `RunResults` type (`fixtures/run-results.ts`) |

Notes:
- A **failed score is `null`**, never `0`. Your code already treats `null` as unavailable.
- `groupings` comes from the backend: up to 5 ranges per numeric column, and one slice per value for columns with ≤ 10 distinct values. The text and ID columns are never grouped. Count documents into the slices as you already do.
- `concepts[].description` can be `""` when a concept matched no documents.
- `scores[].evidence` holds at most one highlight.

### 2.5 Model settings
| Call | Returns |
|---|---|
| `GET /settings/models` | `{ provider: "openai" \| "other", model: "default" \| string, hasKey: boolean }`. The key is never sent back. `"other"` only appears when a developer configured a local model in `.env`; show it as read-only. |
| `PUT /settings/models` | Body: `{ provider: "openai", model, apiKey }`. A blank `apiKey` keeps the saved key. |
| `POST /settings/models/test` | Optional body, the same as `PUT`, so a key can be tested before saving. Returns `{ ok: boolean, error: string \| null }`. |

### 2.6 Errors
Every error response is `{ detail: string }`, FastAPI's default, so you can show `detail` directly. Status codes:
- `400`: no model configured. Send the user to Model settings.
- `409`: the action isn't allowed in the run's current status, e.g. editing a run that isn't a Draft.
- `415`: unsupported file type (ZIP).
- `422`: invalid input, e.g. a bad file or an unknown column.
